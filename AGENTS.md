# OIS Designs project instructions

Before UI planning, mockup revisions or app implementation, read:

- `design-feedback/preferences.md`
- `design-feedback/decisions.md`

Apply confirmed user preferences consistently. Keep proposed designs separate from user approvals. Update the feedback record when the user states a new preference or correction. Do not add unrequested promotional slogans. Use shared treatments for repeated UI states and evaluate navigation choices rather than merely agreeing with feedback.

The current phone design contract is `docs/planning/APP_DESIGN_SPEC.md`; use `docs/planning/BUILD_PARITY_CHECKLIST.md` to prevent omissions. Round 3 supersedes conflicting earlier mockups: plain text brand, combined dimensions, no nudge/centre controls, real 3D furniture, contextual navigation, quick doors, richer materials, locks and read-only Walk. Preserve the Expo starter until the user has approved the mockups. Browser review code and model exports do not establish Expo/native capabilities. Follow `mobile/AGENTS.md` for any work inside the app.
