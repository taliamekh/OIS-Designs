**Current override:** read [round 3 design specification](APP_DESIGN_SPEC.md), [build parity checklist](BUILD_PARITY_CHECKLIST.md), [Home Planner reference](HOME_PLANNER_REFERENCE.md) and [setup after approval](EXPO_AFTER_APPROVAL.md) first. Proposal dated November 8, 2026. **Stop after mockup feedback before implementing app features.** The interactive preview and screenshots are design artefacts; the Expo source remains a starter.

## Design to review now

Eight primary screens: Start, Floor plan, Finishes, Five sets, Placement, Whole house, Settings and Plan upload. A set-detail screen lists five pieces and their footprints. The preview uses actual OIS logo/office imagery; the material accents and furniture are proposed, not official merchandise. [Brand and product research](RESEARCH.md).

### Changes after user review

See [confirmed preferences](../../design-feedback/preferences.md) and [decision record](../../design-feedback/decisions.md). The revised preview adds Doors, Heights, a planned Scan Room information view, a contextual Add menu, and three logo-integration studies. Both unavailable start options use the same right-aligned Coming soon badge. Promotional slogans are removed throughout. Replace the permanent four-tab bottom bar with one editor, stable 2D/3D controls and contextual tools; do not require users to complete finishes before opening furniture.

Phase 1 now includes an editable flat ceiling height. **Phase 2 must demonstrate different per-room flat ceiling heights on the same level**, with the upper floor elevation unchanged, and the five door/opening types (single swing, double swing, surface sliding, pocket sliding, open doorway). Door placement displays width/height, motion clearance and corner distances from both wall faces while moving. Hinge side, swing room and slider travel side belong in the production inspector even where the review diagram simplifies them. Add acceptance for both sides' measurements, opening/ceiling conflicts, panel clearance, cancellation and one-command undo.

Phase 3 geometry refinements include sloped/vaulted ceiling profiles, soffits and double-height voids. Each is a separate working increment with an asymmetric real or authored fixture; a flat height override alone does not count as completing those features. The implementation boundary is documented in [architecture](ARCHITECTURE.md).

- **Start:** manually create a floor plan; Upload your floor plan (Coming soon); Scan Room (Coming soon); continue an existing sample house. A new manual project opens in 2D planning mode.
- **Floor plan:** generic room templates, typed inside-face dimensions, room selection, add rooms and connect a shared doorway. Rectangles first; L-shaped/free polygon outlines follow a separate validation step.
- **Finishes:** tap an individual wall or the floor; contextual controls identify the selected face. Selecting one wall does not repaint every wall. Room switcher avoids backing out to Projects.
- **Furnish:** five coordinated sets with five separate pieces, style/palette thumbnails, exact item footprints and a clear Place action. Initially one-piece placement; no automatic complete-room furnishing.
- **Placement:** top view, selected footprint, visible Grid Snap/Free Move badge, measurements, rotate/nudge, undo and Done. Browse and Place have distinct gesture ownership.
- **Whole house:** later multi-floor dollhouse with All floors/Ground/First, direct room jump, Fit house, cutaway/solid mode. Exploded spacing is a viewing aid; it does not move the actual floors.
- **Settings:** Grid Snap / Free Move; explicit 10 cm default and 15° grid rotation; metric/imperial display; local saving. Account/sync is visibly later work.
- **Upload floor plan:** planned photo/image/PDF → page/floor assignment → recognised-layout review → known-dimension calibration → editable house and 3D. Manual tracing is the fallback when recognition is uncertain. This feature was added following the user's latest request.

## Sequenced working increments

No calendar commitment is made because the deadline, weekly availability and other teammates' experience are unknown. Each phase ends in a running demo and a small usability check; features do not accumulate untested until the end. Dependencies are technical gates, not requests for a fresh permission confirmation at every routine step.

## Proposed support and performance envelope

These are **provisional release targets**, not claims validated by the mockup or starter bundling.

| Surface | Proposed initial target | Capability / fallback |
| --- | --- | --- |
| iOS phone editor | iOS 16.4+; iPhone 11 or later; test standard iPhone 13 as primary reference and a compact-screen model. | Verify installed OS, GL context, texture limits and actual scene performance. If 3D initialization fails, keep 2D dimensions/layout/material choices and saving; explain that 3D is unavailable. LiDAR is not an editor requirement. |
| Android phone editor | Android 12+, 64-bit device, 6 GB RAM target, OpenGL ES 3-class graphics; test Pixel 6a and a mid-range Galaxy A54 or available equivalent. | Framework Android 7 floor is not an OIS performance guarantee. Probe GPU/format support; reduce scene detail, then use 2D fallback. Android capture depends on a separately validated provider. |
| Phone layout | 360–430 logical px release target; inspect at 320 px as a resilience check; safe areas, landscape recovery and large text. | 44 pt / 48 dp effective action targets; clear selected state plus labels; VoiceOver/TalkBack surface list, keyboard numeric alternatives and reduced motion. Preview screenshot text is not a completed accessibility test. |
| Tablets | Later iPadOS and Android tablet matrix, chosen after device availability is known. | Side inspector only when canvas remains useful; compact-width layout returns to phone sheets. |
| Web companion | Later current Windows Edge/Chrome first; capability-gated Safari/Firefox follow. | WebGL capability check and 2D fallback; no claim of native capture from desktop browser. |

Budgets for the first real editor fixture: 8 rooms / 40 placed items; warm local project open to usable plan ≤2 s; usable cached 3D ≤4 s; tap/nudge feedback ≤100 ms; target 60 Hz UI and **at least 30 fps 3D while navigating** at the baseline. Rendering budget: start around ≤200k visible triangles, ≤100 draw calls, ≤128 MB GPU textures, 1k texture maps and ≤2 MB per initial furniture GLB; no real-time shadows/postprocessing on baseline quality. These are starting engineering limits to measure and adjust, not universal hardware thresholds.

Load active room/full-detail first; nearby shell next; other floors simplified. Cap render pixel ratio, render on demand while idle, instance repeated assets, share materials, and release unused resources. Measure after 15 minutes of edits/orbit on physical devices (frame time, memory growth, battery/thermal behaviour) and after 20 room switches. For the six-room/two-floor fixture target ≤350 MB app memory as an initial diagnostic budget, with no progressive growth/crash. If it misses the budget: drop detail/textures/shadows, unload distant rooms, then offer the 2D fallback. Large splat reference layers have their own separate budget; do not spend the whole editor budget on one scan.

### Required scanning-team handoff

- Versioned schema + exporter source/pipeline version; units/frame/origin, scale status/calibration and declared missing fields. Preserve source structure separately from designer overrides.
- Stable wall/floor/opening IDs, ordered floor boundary, interior faces, heights/thickness, doorway positions; scene-mesh or splat alone is insufficient. IDs changing on rescan need explicit mapping/revision policy.
- At least one asymmetric **real LiDAR room** and one **real camera room**, with ≥3 reference tape/laser measurements and recorded errors. OIS must choose acceptable tolerances; no generic centimetre-accuracy claim.
- Asset manifest with actual format/version, byte count, coordinate transform, bounds, required decoder/extensions, hash and licence. PLY extension alone does not specify Gaussian attributes.
- Camera iPhone 13 support statement and evidence, processing location, permission/session ownership, progress/cancel/retry/error codes, resource release and optional server job contract. Test both failed capture and unverified scale.
- Acceptance in the app: independent wall/floor finish changes, known-size placement, optional visual layer disabled, save/reopen, mirror detection and correct shared-house alignment.

The older Unity-oriented project/testing notes and original source fixture remain historical inputs. This proposal supersedes their engine/device assumptions for future implementation, without rewriting those originals during design review.
