# Whole-house static batching investigation

November 10, 2026. This is a measured browser experiment under `spatial/`, separate from the app owner's production house-view integration.

The frozen 40-model house view issues 143 draw calls in this runner (the earlier view-review capture recorded 144). Combining 92 eligible opaque furniture meshes into 24 exact-compatible material/attribute batches reduces the same runner's count to 75, a 47.6% reduction. Rendered triangle count stays 88,206; texture count stays ten, including the floor texture. Three transparent parts remain in their original path.

`spatial/review/static-batches.js` compares material serialization and exact live texture identities, preserves normals/tangents/UVs/colours and indices, and bakes current world transforms into frozen batch geometry. It retains per-face ranges resolving hits to original item IDs. It skips animated, instanced, multi-material, transparent, custom-shader, clipping-plane, reflected-transform, interleaved, partial-draw and nonstandard render-order/layer cases. It owns only the additional geometries. Original materials, maps, item roots, texture-bank leases and project data remain caller-owned.

Evidence: `spatial/evidence/batch-browser-r6/result.json`, with source hashes, before/after screenshots and the complete ray results. Two hundred vertical probes preserve the frontmost item's identity and height within 0.00001m. A 12×12 camera-ray grid preserves all nearest candidate-item hits (13 rays hit furniture). Exact triangle-hit multiplicity at grazing internal seams is not asserted: the first two exploratory runs exposed Float32 edge/duplicate sensitivity, and the report retains raw hit counts. This check concerns picking's nearest surface, not equality of every internal intersection.

Seventeen independent synthetic material/ownership cases also pass in `spatial/evidence/batch-contract-r1/result.json`: distinct tints, roughness, metalness, normal conventions, live maps and alpha thresholds stay separate; unsupported render paths remain original; hidden meshes stay hidden; disposing a batch twice never disposes caller-owned geometry/materials.

Appearance is close, not pixel-identical: 1,262 of 5,374,080 channels change; RMSE 0.1636/255, maximum channel difference 44. World-space Float32 baking changes precision near small edges. The original and batched screenshots must remain available for review.

The cost is 7,083,872 additional attribute bytes plus 523,368 index bytes (7.25MiB), 24 additional geometries, and a measured 76.3ms cold build in the recorded desktop browser. This is one timing sample, not a phone timing claim or stable benchmark. Earlier expansion/image-serialization approaches used more memory and about 674ms; preserving indices and avoiding image encoding improved the measured build. Twenty rebuild/dispose cycles across canonical/separated floors return to the exact warmed resource counters. Restoring the original scene restores draw/triangle counts; complete disposal leaves zero geometries, textures and texture-bank leases.

Production adoption is withheld. The app needs an explicit read-only/static lifecycle, invalidation after geometry/pose/material/scope/visibility changes, batch-aware picking with wall occlusion, safe tint isolation, memory budgeting and frame scheduling, plus source-matched Expo and physical-device measurements. A frozen world batch cannot be moved with a live floor group or reused after orbit-dependent wall changes without deliberate separation of ownership. No batch optimization has been added to `mobile/`, and the original reviewer remains unchanged.
